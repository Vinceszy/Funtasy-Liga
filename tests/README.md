# Tests

```bash
tests/run_all.sh            # in parallel (default: 3 workers), ~4 min
WORKERS=1 tests/run_all.sh # serial mode (for debugging), ~10 min
```

`tests/run_all.sh` runs every test with one command. It starts a local server
(`python3 -m http.server`) on the repository root, runs the tests, and prints a summary.
The exit code is the number of failed tests, so it can be used from CI as well. The order:

1. the fast Python tests, one after the other: `doc_checks.py`, `data_consistency.py`, then
   every `collector_*.py`;
2. the browser tests (`*.test.js`) in parallel, because they are independent of each other —
   each launches its own browser with its own mocks;
3. the two **timing-sensitive** tests (`refresh-indicator`, `refresh-on-return`) at the end,
   alone, because under parallel load they could fail falsely.

Parallel runs depend on `rewriteJson` reading from disk (see `common.js` below): while it went
through the local test server, a connection dropped under load lost the tests' preconditions.

Environment variables:

| variable | read by | meaning |
|---|---|---|
| `PORT` | `run_all.sh` | port of the local server (default: 8910) |
| `WORKERS` | `run_all.sh` | number of parallel browser workers (default: 3; 1 = serial mode) |
| `TEST_BASE` | `common.js` | base URL of the site under test (default: `http://127.0.0.1:8910/`); `run_all.sh` sets it to `http://127.0.0.1:$PORT/` |
| `PLAYWRIGHT_MODULE` | `common.js` | path of the playwright module (default: `/tmp/node_modules/playwright`) |
| `CHROME_PATH` | `common.js` | path of the Chromium binary (default: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`) |

A single test runs on its own too: a Python test with `python3 tests/<file>.py`; a browser
test with a server running on the repository root, as
`TEST_BASE=http://127.0.0.1:<port>/ node tests/<file>.test.js`.

## Files that are not tests

- **`run_all.sh`** — the runner described above.
- **`common.js`** — the shared part of the browser tests. Its exports:
  - `check(cond, label)` — one assertion: prints `OK` or `FAIL` with the label, and records a
    failure in `failures`;
  - `section(title)` — prints a section heading in the output;
  - `failures` — the shared list of failed assertion labels;
  - `launch()` — launches Chromium (`CHROME_PATH`) through Playwright (`PLAYWRIGHT_MODULE`);
  - `finish(browser)` — closes the browser and exits with code 1 if anything failed, 0 if not
    (if Playwright is not found, `common.js` itself exits with code 2);
  - `rewriteJson(page, pattern, transform)` — rewrites a JSON response on the fly: the file is
    read **from disk** (not through the local server, which drops connections under load),
    passed through `transform`, and served instead; a request that is not a repository file
    goes through the network;
  - `blockApis(page)` — cuts off the live APIs, every proxy host of the fetcher's path list and
    Google Fonts, so the page works from the stored data only and the test does not depend on
    the outside network;
  - `blockStoredBreakdowns(page)` — makes the stored breakdowns (`bontasok/<r>.json`) answer
    404, so the page falls back to the live path (see below);
  - `BASE` (the value of `TEST_BASE`) and `chromium` (the Playwright browser type).
- **`legacy-hungarian-names.txt`** — the list of code and documentation files that were named
  in Hungarian before code went English. `doc_checks.py` (D20) fails on a file whose name
  carries a Hungarian word but is not on this list, and on a listed path that no longer exists.
  A file is renamed when it is touched, and removed from the list then: the list may only
  shrink.

## Three principles

- **There are no fixture copies.** Every test runs on the **real** data in the repository.
  Copied JSON files go stale, and a test on them stays green even when the real data has
  changed.
- **The test produces the special states itself, on the fly** — Playwright intercepts the
  request and rewrites the response, and in the collector tests `api_get` is replaced. Not from
  a stored file, so it measures the same thing tomorrow too.
- **Every assertion goes through the shared `check`.** If a test prints "FAIL" by itself, the
  runner only sees the exit code — and takes the failed test for green. This is how
  `zero-points.test.js` hid six failed assertions: its own failure array shadowed the shared
  one, and the exit code only looked at the page's JS errors. Its own array is now
  `pageErrors`: it only collects the page's JS errors, and those too are asserted through
  `check`.

## Measuring the live path: `blockStoredBreakdowns`

The breakdown of a closed round comes from the repository (`bontasok/<round>.json`), and **that
is the primary path**. So a test that measures the **live** path — the fetcher's proxy chain,
the error message, the profile's points filled in row by row — has to cut off the stored file
too, otherwise the page never gets that far, and the test silently measures something other
than it believes. That is what the `blockStoredBreakdowns(page)` helper of `common.js` is for;
`stored-breakdown.test.js`, which measures the stored path, naturally does not call it.

A missing file happens in production too: a round from before stored breakdowns existed, or a
player who is no longer in the current 385-player roster (there are five such in
`squad_history`).

> **The trailing `*` in the route pattern must not be dropped.** The page requests the file
> with a cache buster (`bontasok/4.json?t=…`), and Playwright matches the glob against the
> **full** URL — `**/bontasok/*.json` does not match the ending with the query string, and the
> test silently gets the real file. So every data file route ends in `*`.

## Collector tests (Python, no network)

Most of them replace `api_get` (in `collect_draft.py`: `fetch`) with a mock, and run the
collector in a temporary directory; the rest call the collector's functions directly or read
its source.

| file | what it checks |
|---|---|
| `collector_self_repair.py` | If MLSZ corrects an old round afterwards, whether the collector carries it through — into the results, into the squads (it fetches the round's squads again) and into the cross-check (if the sum computed from the squad does not match the stored official value, the official value is fetched again and written in). It also checks that the per-round squad files (`keretek/`) are written, match the full history, and carry no timestamp. It also guards the `%5B` filters in the query of `rankings`: built with %-formatting they broke the URL, and the backfill branch never ran in production. |
| `collector_provisional.py` | The handling of the `provisional` list: what goes in, what comes out, and what stays unchanged on incomplete data — if the live round's squads cannot be fetched, the provisional flag stays (**C1**); a round already published as final is not reopened by an incomplete run (**C2**). It also checks that with unchanged data the collector rewrites **not a single output file** (**C3**) — not just `results.json`, but every one it finds after the run (the `stamp` is replaced by a counter, otherwise the second-precision timestamp would hide an unneeded write). All of them, because the "only if changed" logic is written separately per file, and exactly this scattering hid the `results.json` bug. A separate case (**C4**): the correction of an **old** round reaches `squad_history.json` but does not rewrite `squads.json` — that holds only the last round's squad, while the condition of the write was a change of the full history. |

With an empty or unknown breakdown `stats` stays the source (on an API change the old behaviour, not zeros); in a double gameweek the two matches add up; on a mismatch the run reports it loudly. |
| `collector_round_close.py` | The nine cases of closing a round (see below). |
| `collector_guardiola.py` | The **Guardiola indicator**: with an unchanged squad **exactly 0** (the assertion that breaks most easily — if the two sides count from different sources, the bench halving slips by 0.01, and the indicator would show "+0.01" although the manager did not touch the squad); a better transfer is positive, a worse one negative, the difference exact; last week's **roles** count (captain, bench); the Hungarian rule applies to the alternative too; no value for the first round and without a breakdown; a player missing from the breakdown gives 0 points. | `collector_squad_moves.py` | The data of the „Változtatások" (Moves) tab (NB1): a sold player counts with last week's role, a bought one with the current role, a role change is a separate item, the difference of the Hungarian rule as well. With an unchanged squad there are no items; nothing to compare with gives no data; without a breakdown (the round has not closed yet) the change still comes out, without point values. |
| `collector_draft_squad_moves.py` | The same on PL, with the extra that **what the human did and what the machine fixed on top of it are separated**: the player items look at the *named* role (bench = 0), the gain of the automatic substitution at closing stands in its own row. **P5**: human + machine = the indicator. | `collector_storage.py` | Writing and reading the **accumulating** files in both collectors. | `collector_contracts.py` | The names the pages and the collectors share, pinned: which **data files** the pages load (and that each exists), their **top-level keys** (the archived rounds included), and the **browser storage keys**. | `collector_efficiency.py` | The NB1 line-up efficiency (`collect.py` `efficiency`): the raw points are worked back from the cap/sub flags, the bench is per position, a perfect line-up is 100%, the possible value does not depend on the actual line-up, and an incomplete squad (not 15 players, or a missing position) gets no value. |
| `collector_roster.py` | Mapping the player roster (missing fields, a row without an id, a failed response; one request with a large page size; the surname first in a long name) and the price log: a new entry only on a change, the earlier value stays, and a missing or zero price does not write a false price drop. |
| `collector_closing_nb1.py` | Logging the post-match points adjustment (`collect.py` `closing_changes`): only a finished match counts as a change, the captain doubling and the bench halving are worked back (rounded to a quarter), the same change appears for every manager affected (as on the PL panel), the same run twice does not duplicate it, the deduplication does not swallow a later new adjustment, missing data invents no change, and a player transferred out gets no entry. |
| `collector_breakdowns.py` | Saving the itemised breakdown of closed rounds (`collect.py` `collect_breakdowns`): a file is made for a closed round, not for one still in progress; the second time there is not a single request; after an MLSZ correction it fetches again; with many failed requests it does **not** write a half-finished file (one or two failures are tolerated); a player without points is stored with an empty list (that is different from missing). | `collector_draft_closing.py` | The Draft collector finalising a round: a round not yet closed is fetched again even with a complete squad, **after lockdown** once more (that is when the automatic substitution comes in), and once `current_event` has moved on, never again — and after an incomplete fetch it is **not** marked final. | `collector_matches.py` | The collector's match collection (`meccsek.json`): merged by id and sorted by kick-off, **a result only from a finished match** (the score of a match in progress is not stored even if the API sends it; a finished 0–0 is a real result), a match falling back from another round is left out, a complete round asks for no more match list, one with a match in progress does — and the **rescheduled match** gets in too: if the round's official points change, the request with the match list goes again (the postponed match is not in the list, so it would not show as "unfinished"). **M7**: every request with the match list asks for `home_team` and `away_team` (otherwise the live round's match has no clubs, and `"?"` is stored); **M8**: a round with `"?"` clubs is fetched again. **M9–M10**: the *rescheduled* (earlier round's, now played) match counts in the round, the club does not get a "no match" flag, `start` points to the nearest match not yet finished, and `vege` is set only when all of them are finished — the *falling-back* match still drops out. **M11**: when the match list has just been fetched, the old `nogame` does not stick (without it the fix would have blocked itself); without a match list it is still inherited. |

### The cases of `collector_round_close.py`

| case | assertion |
|---|---|
| R1 | On the **first** run, when there is no earlier `provisional` entry yet, the round is not written as final after a failed squad fetch either. |
| R2 | If the round's last match is **still in progress**, but MLSZ already gives `is_played=true` for everyone, the round stays provisional. |
| control | If the match has **finished** (`completed`), the round does close. |
| R3 | A player who has **no match** in the round (postponement) does not hold up the closing. |
| R3b | The same when the round is no longer the current one, so the match list is not requested — the flag comes from the **stored** squad. |
| R4 | **Safety net:** if the player-level picture does not come together, but MLSZ has already moved past the round, it closes anyway. |
| R5 | …but while MLSZ says **this** is the current round, the net does not fire. |
| R6 | If the match list returns a match of **another round** (for an old round the API falls back to the club's latest match), that is "no match" too — and the state of that match cannot hold up the closing. |
| R7 | A squad in the **old format** (no `played` in it) is fetched again by the collector, and the filled-in record has `id`, `played` and `nogame`. |

## A calendar-dependent constant goes stale sooner or later

During a season the **data moves** under the tests, and a hard-coded number or "the first
stored round" comes to mean something else sooner or later. Six assertions failed this way at
once, none of them a product bug:

| Test | What it assumed | What it led to |
|---|---|---|
| `refresh-indicator`, `live-auto-refresh`, `refresh-on-return`, `live-points-from-breakdown`, `match-state` | the **first** stored round is the live one | the home page lists the **latest** one, so the click went to a non-live match, and the measurement silently measured nothing |
| `nb1-closing-adjustments` | the last round played is round **5** | once round 6 closed, the pager stood on round 6 |
| `squad-moves` | 120 ms is enough to draw the list | as the data grew, it slipped out of the window |

The rule for these: **the precondition must be stated, not inherited from the repository's
current state.** Either it is computed from the data (the latest stored round,
`T.lastPlayedRound`, the list of rounds played), or the test produces it on the fly (removing
the round's result with `rewriteJson`). And instead of a fixed wait, wait for a **state**.

## Tests that measure the live round make the LATEST stored round live

Five tests (`refresh-indicator`, `live-auto-refresh`, `refresh-on-return`,
`live-points-from-breakdown`, `match-state`), and partly `squad-moves`, rely on a round being in
progress on the PL page. With a single stored round it did not matter which one they made
live — it was the only one. With several, they diverge: the home page lists the latest round,
so a test that made the *first* one live clicked a non-live match, and the measurement silently
measured nothing (the indicator never appeared, the live score was never written). Four
assertions failed this way, none of them a product bug.

So each of them makes the **latest** stored round live, and where needed also removes its
result from the schedule (`rewriteJson`) — that is, it **states** the precondition instead of
inheriting it from the repository's current state. The same rule applies to every test that
measures a live round: a precondition that depends on the calendar goes stale sooner or later,
and then the test does not report an error, it falls silent.
